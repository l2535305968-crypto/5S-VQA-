# 5S × VQA 协同调用规范 v2.0

## 1. 边界

- **5S**：生成之前与修改之前的创作计划，描述主体、风格、结构、材质、规格；保留《5S法 V1.0》完整定义。其生成后基本自检不被撤销。
- **VQA**：独立的质量审核，针对实际结果建立问题清单、证据、技术检查、返工决策；不替用户擅自改变艺术方向。
- **Registry**：负责可复用的媒介/风格评估规律，不能替代用户指定作品的审美目标。
- **Scripts**：只检验可以客观读取的文件事实，不能替代观察、比较和审美判断。

## 2. 任务前：5S输出一张“审核输入卡”

填写任务ID、用途、输入类型（原创/参考/修复/局改/放大/宣传）、源文件与版本、用户硬性约束、允许变更区、禁止变更区、风格媒介配置ID、项目覆盖配置ID、目标宽高像素、格式、文字要求、重要局部、质量权重与未知信息。

缺项默认“未知”或“待定”，不得用模型猜测强行填入；如必须完成任务而未指定规格，标记自选值是建议，而非用户确认值。参考图保真任务明确哪些内容可改、哪些不能改。

## 3. 生成中：减少失真源头

- 生成提示词优先描述可见、可验证的特征，而非重复“8K/极致/超高清”形容词。
- 建立角色/建筑/产品恒定结构锚点，保持镜头和风格一致；混合风格请规定不同区域的适用规则。
- 原生像素由模型/工具实际输出决定；提示词中的4K文字不能替代尺寸设置。
- 从高质量候选中筛选；严重N2伪纹理、形变和关键结构错误应先回到生成阶段，而非直接放大。

## 4. 生成后：VQA逐层核查

1. 全图缩略视角（构图、气质、重点与大片区域问题）。
2. 实际像素100%（主体、边缘、纹理、暗部、平滑渐变、文本区域及项目特殊区域）。
3. 与参考母版或其他帧对照（只在有依据时判断保真/一致性）。
4. 运行脚本核实实际像素、格式、ICC/EXIF信息和局部截图；分辨率原生性仍须由生成记录证明。
5. 根据对应风格配置判定“艺术性有意效果”与“非意图缺陷”；未知风格使用临时档案。
6. 出具Q1-Q7分数（有可靠证据才评分）、缺陷P0-P3、硬性门槛与最终等级。

## 5. VQA → 5S返工映射

| VQA问题 | 反馈给5S | 优先修复 |
|---|---|---|
| 主体、身份、物体错误 | S1 | 重新约束识别锚点/局部重绘 |
| 风格错配或色彩冲突 | S2 | 调整样式规则/分区重绘 |
| 视角、透视、比例、连接错误 | S3 | 结构参考/局部或整体重生 |
| 材质、纹理、模糊、伪影 | S4 | 根据N分类定向处理 |
| 分辨率、格式、交付错误 | S5 | 正确导出/谨慎放大并重验 |
| 多项并发 | 依根因排序 | 先修结构，再修局部细节，最后技术导出 |

## 6. 迭代保护规则

- 一个返工轮次只聚焦有限的高优先级缺陷；每轮写明“变更项/保留项/禁止项”。
- 不把 `edit1→edit2→edit3` 无止境串接；差异扩大时回到 `source_master` 或已验收的干净候选。
- 只有一个小区域失败时优先局部蒙版，已合格区域不得因修复而退化。
- 插值放大只提高像素数量；AI超分重建需检查是否产生假纹理或改变文字/五官/Logo。
- 同一路径连续三次修复失败，停止重复参数尝试并建议更换源图、工具或工作流。
- 每次复审记录前后版本的已修复问题、新引入问题及未解决问题。

## 7. 交付闸门

- **硬闸**：任务明确硬需求、关键主体、关键结构/功能、文字准确性（当明确要求）、交付像素/格式；失败即不得“合格交付”。
- **软闸**：美学表现、轻微不影响用途的局部瑕疵，按风格配置、用途、项目门槛讨论。
- 技术闸门未检验即标注“未验证”，不能说“4K验收通过”。
- 非摄影媒介不能以摄影锐度为默认合格条件；抽象作品不能以真实解剖或真实透视为普遍硬闸。

## 8. 批次任务

每图独立5S/VQA记录；同时审核跨图主体恒定元素、画风、光影语法、场景尺寸、分辨率、镜头与时间连续性。单图通过不代表整组通过。允许项目配置声明不同画面的例外。视频需附关键帧和时间点，不能只用一张截帧代替全片检查。
