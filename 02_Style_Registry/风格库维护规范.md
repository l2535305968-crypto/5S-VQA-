# Visual Style Registry 维护规范 v2.0

## 1. 使命：风格库不是风格分类学的终点

此库是**开放式、增量式、可修订**的审核配置仓库，任何时代、任何媒介、任何用户命名或模型产生的新表达形式均可建档。预置摄影、二维、3D、水墨等仅为示范，不是强制类别、全集、固定树形分类，也不是默认美学等级。风格可以交叉、局部混合、渐变、故意违背物理、拥有尚无通用名称的技法。

不能因为一个作品不属于任何已知类别就打低分，也不能先把它粗暴归为最近似风格再套不适用的检查项。优先理解任务意图及其自洽的视觉规律。

## 2. 三层标准与组合

- `VQA Core`：不变的事实诚信、需求符合、审核证据、结构合理性（对当前媒介定义）、质量等级和交付门槛。
- `Style/Medium Profile`：媒介呈现规律、特定视觉目标、刻意保留的效果、易发缺陷、检查区域、验收门槛。
- `Project Override`：该系列特有角色锚点、配色、文字、交付尺度等，必须显式指定项目才能启用。

组合冲突优先级：安全/法规 > 用户明确要求 > 参考保真 > 项目覆盖 > 指定Style Profile > 通用默认。多风格同时启用时，先判断**空间分区**（人物动漫、背景水彩等）或**表现维度**（线稿A、色彩B、光影C），明确各Profile管辖范围；冲突规则没有答案时生成临时组合Profile并标注假设，必要时向用户确认。不同风格不能相互否定对方的有意效果。

## 3. Profile不可缺少的内容

每个档案采用 `风格配置模板.md` 的全部字段。结构化源存为JSON，格式以 `profile.schema.json` 为准；阅读版可另存md。至少包括：

| 字段 | 作用 | 典型校验对象 |
|---|---|---|
| profile_id / display_name / aliases | 身份及别名 | 避免同义重复 |
| version / status / change_history | 版本生命周期 | 追踪谁改了什么 |
| scope | style / medium / project | 不让项目规则全局化 |
| description / intent | 美学意图、适用边界 | 不对未知美学自作主张 |
| medium | 制作方式与视觉媒介 | 摄影并不等于写实 |
| visual_rules | 几何、色光、纹理、边缘、细节等 | 风格内部一致性 |
| intentional_effects | 有意存在的粗糙、抽象、颗粒、虚焦等 | 避免错误降噪 |
| defect_rules | 确定的异常与检查手段 | 避免“感觉不够高清” |
| inspection | 全图、100%局部、专属区域、比较方式 | 形成可重复检查路径 |
| acceptance | 硬闸/软闸/不适用项/项目门槛 | 避免单个高分掩盖失败 |
| compatibility | 兼容、冲突、优先级说明 | 混合风格组合 |
| references | 真实参考/用户定义/来源与授权 | 防止伪造风格证据 |
| extensions | 任意新领域自定义字段 | 不封死未来扩展 |

使用JSON只是为便于机器检查。新媒介需要新的独立维度时，可先放 `extensions`，然后评估是否值得更新通用Schema。不要为了机器校验限制艺术表达。

## 4. 发现未知风格时的操作程序（强制）

### 阶段 U0：判定与诚实标注

搜索名称、同义词、视觉轴向与相似Profile。若找不到充分匹配，标记 `UNRECOGNIZED`；不等于“错误”。分析不能从模糊的风格名称直接推导已有模型不存在的精确参数。

### 阶段 U1：抽取可观察证据

记录用户语言、参考样本、媒介、线条、纹理、色彩、光源、结构、细节密度、关键不变量、刻意违反现实规律之处以及真正可能影响用途的缺陷。至少分开写“看到的事实/合理假设/尚不确定”。

### 阶段 U2：创建临时Profile

在 `Temporary/` 新建 `profile_id.draft.json` 或输出等价临时审计卡，`status=draft`；创建时间、临时版本、证据与未知项必须记录；对无法定义的检查项填“待定”，不能默认为“不合格”。即使没有用户批准存盘，也可在当前任务内暂用临时Profile。

### 阶段 U3：按临时规则审核

先执行VQA通用核心，风格专属部分使用临时Profile。审查时把假设与判断分开，提供可修订的证据与疑点。允许定向请求更多样本，但不能因此阻止本来可以完成的基础审核。

### 阶段 U4：确认并入库

只有用户明确希望保存为正式长期规则时，才能将draft升为 `approved` 并放入 `Profiles/`，更新 `registry.json`、变更记录、关联版本。未获得确认则保留为临时审计卡，绝不声称已正式收录。

### 阶段 U5：复验与迭代

从不同样本复验规则是否对同风格适用，是否误判意图纹理；新增缺陷模式、减少误判、补充关键区域；在 `change_history` 中记录依据。出现重大不兼容变化提高主版本，旧档案迁入历史归档。

## 5. 风格修改、合并、拆分、废弃

**修改**：先备份当前Profile；变更验收阈值与缺陷定义要记录原因、旧新值、影响的项目与样本；小幅补充用补丁版本，新增规则用小版本，破坏性变化用主版本。更改后一并运行校验脚本和样本回归。

**合并**：仅当视觉目标、适用媒介、允许效果和审核门槛真正兼容时合并；记录别名和合并前的ID，避免历史报告断链。不要只因名称相似而合并。

**拆分**：当同一Profile覆盖明显不同的媒介逻辑、局部区域或标准互相矛盾时，拆出子Profile并说明适用条件与迁移路径。

**废弃**：先标记 `deprecated` 并写替代ID、理由、最后兼容版本；旧配置迁至 `旧（old）` 或单独归档，禁止直接删除影响可追溯性。

**项目配置独立**：个别项目的“必须9:16、必须黑色背景、人物指定发型”等不可合并进通用风格Profile，更不能写死为全局标准。

## 6. 混合风格审核的细则

1. 定义混合方式：图层/区域/对象/时间帧/视觉维度；一张图可能有多个Profile有效。
2. 每项检查绑定适用范围（如人物轮廓、建筑纹理、背景水墨），范围以外的规则不扣分。
3. 若A要求干净平涂、B要求粗粒纸纹，应明确哪一区域适用哪种标准；全图分区审查，再审查过渡连接是否自然。
4. 对难以分区的实验混合媒介，以用户定义的总体视觉目标作为临时配置核心。
5. 项目变更风格时应保留版本；旧作品应按当时生效的配置版本重现审核，不应被新规则追溯性误判。

## 7. 质量阈值的设定

默认七维权重由VQA核心提供，Profile可以声明N/A项和更高标准；调整权重须给出用途和理由。`minimum_total_score` 是有证据评分下的参考门槛，必须同时满足硬闸。无需在所有作品上强制物理材质、脸部细节或高频纹理。特别是像素艺术应检查像素边界与像素网格，不以光滑抗锯齿为普遍目标。

## 8. 检查与索引

`registry.json` 只收录已批准且当前有效、或已标记deprecated但仍需追溯的Profile。`Temporary/` 不自动纳入索引。每次编辑运行：

```bash
python 04_Scripts/validate_registry.py
```

脚本校验索引路径、关键字段、版本、重复ID、JSON Schema（若环境有jsonschema则额外执行完整Schema）；**校验通过不代表艺术风格定义本身正确**。必须辅以人工样本复验。

## 9. 推荐新增风格请求格式

“请将【风格名称/描述】作为新风格候选；以【样例或文字】提取媒介与视觉规律；保留【有意效果】，重点检查【缺陷】；先输出临时Profile和VQA审核，待我确认后再正式入库。”

“请修改已存在的【profile_id】第【字段/规则】，原因是【具体样本问题】，保留其他规则，给出向后兼容性与回归测试清单。”

## 10. 风格不是封闭枚举

文档中任何样例、模型名、风格名、缺陷类别或媒介类型，都不表示穷尽。可以在 `extensions` 中添加新视觉物理、新检查技法、新坐标方式、新生成模型特性，经过验证后再酌情升级主Schema。不应因一个未预见的新参数与旧模板不匹配就拒绝作品或删除该参数。
